# Module 04: 核验执行模块 (Verification Execution)

> **模块类型**: 核心业务模块  
> **依赖文档**: [00_Global_Architecture.md](../00_Global_Architecture.md)  
> **目标用户**: 甲方运维经理、乙方外部服务团队

---

## 1. 模块概述

核验执行模块是OpsPilot平台的**核心执行层**，支撑甲乙双方在工作项上的协作。乙方团队按工作项要求执行并上传交付物，甲方团队对交付物进行核验并给出结论。

### 1.1 核心职责

- 工作项任务分配和追踪
- 交付物上传和管理
- 多维度核验执行（人工/脚本/AI）
- 核验结论记录和追溯
- 执行进度实时监控

### 1.2 核验流程

```
接收任务 → 执行工作项 → 上传交付物 → 触发核验 → 获取结论 → 完成/重试
```

## 2. 功能需求

### 2.1 工作项任务管理

#### 2.1.1 任务分配

| 分配方式 | 说明 |
|---------|------|
| 自动分配 | 基于计划自动分配给关联的乙方团队 |
| 手动分配 | 甲方运维经理手动指定执行人 |
| 主动领取 | 乙方团队主动领取待处理任务 |

#### 2.1.2 任务视图

**乙方团队视图**:
- 待处理任务列表
- 进行中任务列表
- 已完成任务列表
- 任务详情和执行入口

**甲方运维经理视图**:
- 全部任务列表
- 按计划筛选任务
- 审核待办列表
- 任务执行统计

### 2.2 交付物管理

#### 2.2.1 交付物上传

| 功能 | 说明 |
|-----|------|
| 单文件上传 | 支持PDF、Word、Excel、图片等格式 |
| 批量上传 | 一次上传多个交付物 |
| 版本管理 | 同一交付物可上传多个版本 |
| 格式校验 | 自动校验文件格式是否符合要求 |

#### 2.2.2 交付物要求

根据工作项模板配置，校验交付物：
- 必填性检查
- 格式检查
- 大小限制（单个文件最大20MB）

### 2.3 核验执行

#### 2.3.1 三种核验方式

| 核验方式 | 优先级 | 适用场景 | 执行方式 |
|---------|-------|---------|---------|
| 脚本验证 | 最高 | 系统配置、基线检查 | SSH远程执行脚本 |
| AI分析 | 中 | 文档类交付物分析 | 自动提取关键信息 |
| 人工核验 | 兜底 | 复杂场景、最终确认 | 人工审核确认 |

#### 2.3.2 脚本验证

**执行规则**:
- 执行环境：SSH远程执行
- 执行用户：具有sudo权限的运维账户
- 超时时间：300秒
- 输出格式：JSON
- 结果判定：所有检查项通过才算整体通过

**脚本类型**:
- 系统基线检查脚本
- 软件部署验证脚本
- 安全加固检查脚本

#### 2.3.3 AI分析

**分析规则**:
- 文档格式：支持PDF、Word、Excel
- 关键字段提取：结论、漏洞等级、数量
- 置信度要求：≥0.85
- 人工复核：高风险项目需人工确认

**适用交付物**:
- 安全扫描报告
- 测试报告
- 验收文档

#### 2.3.4 人工核验

**核验流程**:
1. 查看交付物内容
2. 对照验收标准检查
3. 填写核验意见
4. 给出核验结论

### 2.4 核验结论

#### 2.4.1 结论类型

| 结论 | 编码 | 说明 | 后续操作 |
|-----|------|------|---------|
| 通过 | passed | 完全符合验收标准 | 标记完成，进入下一工作项 |
| 不通过 | failed | 不符合验收标准 | 退回，要求重新准备 |
| 待改进 | improvement | 基本符合，有优化空间 | 记录问题，允许通过但需后续改进 |

#### 2.4.2 结论判定

详见 [00_Global_Architecture.md](../00_Global_Architecture.md) 第7.2节

### 2.5 进度监控

#### 2.5.1 整体进度计算

```
整体进度 = Σ(各核验任务进度 × 权重) / 总权重

默认权重：
- 服务对象台账: 15%
- 基础资源交付: 25%
- 权限移交: 15%
- 安全基线: 25%
- 监控告警: 20%
```

#### 2.5.2 实时监控

- 计划整体进度
- 各工作项状态
- 交付物上传状态
- 核验结论统计

## 4. 状态流转

### 4.1 工作项状态流转

详见 [00_Global_Architecture.md](../00_Global_Architecture.md) 第6.2节

```
待处理(PENDING) → 进行中(IN_PROGRESS) → 已完成(COMPLETED)
                        ↓
                    已拒绝(REJECTED)
                        ↓
                    重新执行
```

### 4.2 交付物状态流转

详见 [00_Global_Architecture.md](../00_Global_Architecture.md) 第6.3节

```
待上传(PENDING) → 已上传(UPLOADED) → 核验中(VERIFYING) → 已通过(PASSED)
                        ↓
                    不通过(FAILED) / 待改进(IMPROVEMENT)
```

## 5. 业务规则

### 5.1 强制管控规则

- **不上传交付物无法提交审核**
- **不审核通过无法进入下一节点**
- **关键项必须专家人工审核**

### 5.2 验证方式优先级

```
脚本验证 > AI分析 > 人工核验
```

### 5.3 交付物版本规则

- 同一工作项可上传多个版本的交付物
- 新版本交付物上传后，旧版本自动归档
- 核验结论只针对最新版本的交付物

### 5.4 结果追溯规则

- 所有核验结果永久保存
- 支持历史版本对比
- 支持核验过程回放（脚本验证）
- 支持AI分析过程查看

## 6. 接口定义 (待补充)

### 6.1 工作项接口

- `GET /api/work-items` - 查询工作项列表
- `GET /api/work-items/:id` - 获取工作项详情
- `PUT /api/work-items/:id/start` - 开始执行工作项
- `PUT /api/work-items/:id/complete` - 完成工作项

### 6.2 交付物接口

- `POST /api/deliverables` - 上传交付物
- `GET /api/deliverables` - 查询交付物列表
- `GET /api/deliverables/:id` - 获取交付物详情
- `DELETE /api/deliverables/:id` - 删除交付物

### 6.3 核验接口

- `POST /api/verification-results` - 提交核验结论
- `GET /api/verification-results` - 查询核验结果
- `POST /api/verification-results/script` - 触发脚本核验
- `POST /api/verification-results/ai` - 触发AI核验

### 6.4 进度接口

- `GET /api/progress/:planId` - 获取计划进度
- `GET /api/progress/dashboard` - 获取进度仪表盘数据
