## 1. 产品概述

### 1.1 一句话描述
仿真运维经理是一个业务上线发版前的准入管理系统，通过标准化工作流、自动化报告分析和交付物管理，帮助运维经理确保系统上线前满足所有运维准入要求。

### 1.2 目标用户
- **主要用户**：运维经理（责任方，负责准入审核）
- **次要用户**：
  - 运维专家（定义工作流模板和验收标准）
  - 系统管理员（提供台账数据、执行验证脚本）
  - 开发团队（提交交付物、配合整改）
  - 安全团队（提供安全扫描报告）

### 1.3 核心价值主张
替代传统的纸质/Excel检查表和人工审核方式，通过：
1. **标准化工作流**：预定义上线前检查步骤，确保不遗漏
2. **智能报告分析**：自动读取交付物内容，AI辅助判断合规性
3. **脚本自动化验证**：直接在服务器执行验证脚本，比截图更准确可靠
4. **集中化交付物管理**：所有文档、脚本、报告统一归档
5. **可视化进度跟踪**：实时掌握准入检查状态和阻塞点

## 3. 计划管理模块（新增）

### 3.1 模块概述

计划管理是系统的核心功能模块，用于管理业务上线计划的全生命周期。运维经理通过该模块创建和管理上线计划，关联工作流，生成数据标签，并跟踪核验任务的执行情况。

### 3.2 计划分类

| 分类编码 | 分类名称 | 说明 | 默认工作流 |
|---------|---------|------|-----------|
| STANDARD | 标准上线 | 常规业务系统上线 | 标准上线检查流程 |
| BUSINESS | 业务需求 | 业务驱动的变更需求 | 业务变更检查流程 |

### 3.3 计划生命周期

```
草稿(DRAFT) → 待执行(PENDING) → 执行中(IN_PROGRESS) → 已完成(COMPLETED)
     ↓              ↓                    ↓                      ↑
   创建中      到达执行时间         核验任务进行中          所有任务完成
     ↓              ↓                    ↓                      ↑
   编辑信息    自动/手动启动        进度实时更新           生成报告
```

### 3.4 计划核心属性

#### 3.4.1 基本信息

| 字段 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| plan_id | string | 是 | 计划唯一标识（系统自动生成，如 PLAN-20240322-001） |
| name | string | 是 | 计划名称 |
| category | enum | 是 | 计划分类：STANDARD/BUSINESS |
| priority | enum | 是 | 优先级：P0(紧急)/P1(高)/P2(中)/P3(低) |
| planned_start_time | datetime | 是 | 计划执行时间 |
| planned_end_time | datetime | 否 | 计划结束时间（预估） |
| description | text | 否 | 计划说明 |
| involved_systems | array | 是 | 涉及的应用系统列表 |
| status | enum | 是 | 计划状态 |

#### 3.4.2 审批材料

| 材料类型 | 格式 | 说明 |
|---------|------|------|
| 会议纪要 | PDF/Word/图片 | 线下评审会议纪要 |
| 审批邮件 | PDF/图片 | 邮件审批截图 |
| 其他截图 | 图片 | 其他审批凭证 |

#### 3.4.3 数据标签

系统自动生成计划标签，用于关联5大核验任务的范围：

**标签格式**: `{PLAN-ID}-{CATEGORY}-{TIMESTAMP}`

**示例**: `PLAN-20240322-001-STANDARD-1711072800`

**标签应用**:
- 台账管理：打上标签的服务器纳入核验范围
- 基线核验：标签关联的系统纳入检查范围
- 报告分析：按标签筛选相关交付物

### 3.5 计划创建流程

```
运维经理收到线下审批通过的上线申请
    ↓
进入计划管理 → 点击"创建计划"
    ↓
填写计划基本信息
    ├── 选择计划分类（标准上线/业务需求）
    ├── 设置优先级
    ├── 选择执行时间
    ├── 填写计划说明
    └── 选择涉及的应用系统
    ↓
上传审批材料
    ├── 会议纪要
    ├── 审批邮件
    └── 其他截图
    ↓
关联工作流
    ├── 选择既有标准工作流
    └── 或创建自定义工作流
    ↓
系统自动生成数据标签
    ↓
保存计划（草稿状态）
    ↓
到达执行时间自动启动
    或手动启动计划
```

### 3.6 计划仪表盘

#### 3.6.1 统计卡片

| 指标 | 说明 | 计算方式 |
|-----|------|---------|
| 计划总数 | 所有计划数量 | COUNT(*) |
| 进行中 | 状态为执行中的计划 | status = 'IN_PROGRESS' |
| 待执行 | 状态为待执行的计划 | status = 'PENDING' |
| 已完成 | 状态为已完成的计划 | status = 'COMPLETED' |
| 已延期 | 超过计划时间未完成的计划 | planned_start_time < NOW() AND status != 'COMPLETED' |

### 3.8 标签管理

#### 3.8.1 标签生成规则

```python
def generate_plan_tag(plan_id, category, timestamp):
    category_code = "STD" if category == "STANDARD" else "BUS"
    return f"{plan_id}-{category_code}-{timestamp}"
```

#### 3.8.2 标签关联机制

- **自动关联**：创建计划时，涉及的应用系统自动打上标签
- **手动关联**：在台账管理中手动为服务器/账户打标签
- **范围查询**：通过标签筛选纳入计划范围的所有资源

#### 3.8.3 标签应用示例

```
计划 PLAN-20240322-001-STANDARD-1711072800 创建
    ↓
涉及系统：订单系统、支付系统
    ↓
自动打标签到：
    - 订单系统的所有服务器
    - 支付系统的所有服务器
    - 相关账户信息
    ↓
基线核验时：
    - 只检查带此标签的服务器
    - 生成带标签的执行报告
```

### 3.9 用户场景

**场景1 - 创建标准上线计划**
- **角色**: 运维经理
- **触发条件**: 收到线下审批通过的上线申请
- **操作步骤**:
  1. 进入计划管理仪表盘，点击"创建计划"
  2. 选择计划分类为"标准上线"
  3. 填写计划名称（如：订单系统V2.0上线）
  4. 设置优先级（P1-高）
  5. 选择计划执行时间
  6. 选择涉及的应用系统（订单系统、支付系统）
  7. 填写计划说明
  8. 上传会议纪要、审批邮件截图
  9. 关联标准工作流"标准上线检查流程"
  10. 系统自动生成数据标签
  11. 保存计划
- **预期结果**: 计划创建成功，关联资源自动打标签，到达执行时间后自动启动核验任务

**场景2 - 查看计划仪表盘**
- **角色**: 运维经理
- **触发条件**: 需要了解所有计划的执行情况
- **操作步骤**:
  1. 进入计划管理仪表盘
  2. 查看统计卡片了解整体情况
  3. 查看计划列表，按状态/优先级筛选
  4. 点击具体计划查看详情
  5. 查看5大核验任务的执行情况
- **预期结果**: 全面掌握计划执行进度，及时发现延期风险

**场景3 - 通过标签管理核验范围**
- **角色**: 运维经理
- **触发条件**: 需要确认某计划的核验范围
- **操作步骤**:
  1. 进入计划详情，查看数据标签
  2. 点击"查看关联资源"
  3. 查看已打标签的服务器列表
  4. 在台账管理中补充遗漏的服务器标签
  5. 确认核验范围完整
- **预期结果**: 确保计划涉及的所有资源都纳入核验范围

## 3. 知识库管理模块（新增）

### 3.1 知识库概述

知识库是系统的核心基础设施，用于集中管理运维相关的验收要求、基线标准、操作手册等文档。通过智能匹配引擎，实现验收标准的自动关联和生成。

### 3.2 知识分类体系

#### 3.2.1 预置五大核心功能分类

| 分类编码 | 分类名称 | 说明 | 关联工作项类型 |
|---------|---------|------|--------------|
| INV | 服务对象台账收集 | 应用系统、云服务、账户台账相关规范 | inventory |
| RSD | 基础资源标准化交付 | 系统基线、软件部署相关规范 | resource_delivery |
| PHO | 生产环境权限移交 | 账户权限、访问控制相关规范 | permission_handover |
| SBL | 安全基线核验 | 安全加固、漏洞扫描相关规范 | security_baseline |
| MON | 监控告警配置确认 | 监控指标、告警规则相关规范 | monitoring |

#### 3.2.2 自定义分类

支持用户根据实际业务需求创建自定义分类：
- 分类名称
- 分类描述

### 3.4 智能匹配引擎

#### 3.4.1 匹配流程

```
创建工作项/验收标准
    ↓
识别工作项类型（inventory/resource_delivery等）
    ↓
从知识库检索相关分类
    ↓
基于关键词/标签匹配知识条目
    ↓
按相关度排序推荐
    ↓
用户选择/确认知识条目
    ↓
自动生成验收标准
    ↓
保存关联关系
```

#### 3.4.2 匹配规则

| 匹配维度 | 权重 | 说明 |
|---------|------|------|
| 工作项类型匹配 | 40% | 知识条目关联的工作项类型 |
| 关键词匹配 | 30% | 标题、内容、标签中的关键词 |
| 分类匹配 | 20% | 所属分类的关联度 |
| 使用频率 | 10% | 历史使用次数 |

#### 3.4.3 自动生成功能

基于选中的知识条目，系统自动生成验收标准：

**从Markdown生成**:
- 解析标题作为验收内容
- 解析列表项作为检查点
- 提取交付物要求

**从Word生成**:
- 提取章节标题
- 识别表格中的检查项
- 提取交付物说明

**从Excel生成**:
- 每行作为一个检查项
- 列映射到验收标准字段
- 支持批量导入

### 3.5 版本管理

#### 3.5.1 版本控制规则

1. **草稿版本**: 可随意编辑，不影响已关联的验收标准
2. **发布版本**: 发布后创建快照，关联的验收标准引用此版本
3. **版本更新**: 更新知识条目时，可选择：
   - 创建新版本（不影响历史关联）
   - 覆盖当前版本（提示用户确认影响范围）

#### 3.5.2 版本历史

- 保留所有历史版本
- 支持版本对比
- 支持回滚到指定版本

## 6. 业务规则

### 6.1 工作流规则

1. **工作流模板版本管理**：
   - 已发布（active）的工作流不能直接修改，需要创建新版本
   - 草稿（draft）状态可随意编辑
   - 归档（archived）的工作流不能再创建实例

2. **工作项依赖**：
   - 有依赖的工作项必须在前置工作项完成后才能开始
   - 系统应自动计算关键路径
   - 阻塞的工作项应明确提示阻塞原因

3. **预置工作流保护**：
   - 系统预置的标准工作流（含三大核心检查项）不能删除
   - 可以基于预置工作流创建副本进行自定义

### 6.2 验收标准规则

1. **验证方式优先级**：
   - 脚本验证 > AI分析 > 人工核验
   - 脚本验证最准确可靠，优先使用
   - AI分析适用于文档类交付物
   - 人工核验作为补充手段

2. **交付物要求**：
   - 每个验收标准必须明确所需交付物
   - 支持多种格式：Excel/Word/PDF/脚本报告
   - 交付物上传后自动关联到工作项

3. **自动分析触发条件**：
   - 交付物上传后自动触发（可配置）
   - 或手动点击"开始分析"触发
   - 分析中状态应显示进度

### 6.3 结果判定规则

| 结果状态 | 判定条件 | 说明 |
|---------|---------|------|
| **通过** | 所有必填验收标准均满足 | 工作项完成，可进入下一步 |
| **不通过** | 存在必填验收标准不满足 | 需要整改后重新提交 |
| **待改进** | 非必填标准不满足，或存在建议项 | 可选优化，不影响上线 |
| **未开始** | 尚未进行分析或确认 | 初始状态 |

## 7. 非功能需求

### 7.1 性能需求

- 工作流列表查询：< 500ms
- 脚本执行（单台服务器）：< 30s
- 报告分析（普通文档）：< 10s
- 报告分析（大型文档）：< 30s
- 仪表盘数据加载：< 1s

### 7.2 安全需求

- 脚本执行权限控制（仅授权服务器）
- 交付物文件类型白名单控制
- 文件大小限制（单文件<50MB）
- 敏感信息自动脱敏（如密码、密钥）

### 7.3 扩展性需求

- 支持自定义验证脚本
- 支持自定义工作项类型
- 支持接入第三方AI分析服务
- 支持自定义报告模板

### 8.2 验收标准模板示例

**系统基线配置验收标准模板**：

```yaml
检查项: 系统基线配置
详细标准:
  - 项目: 系统账户安全
    要求: 符合《账户创建以及权限》基线要求
    验证方式: 脚本执行
    
  - 项目: 磁盘分区合规
    要求: 系统盘与应用/数据盘物理或逻辑隔离
    验证方式: 脚本执行
    
  - 项目: 网络安全
    要求: 防火墙策略最小化，仅开放必要端口
    验证方式: 脚本执行
    
  - 项目: 系统基础环境配置
    要求: 时区同步(NTP)、字符集(UTF-8)
    验证方式: 脚本执行
    
  - 项目: 自动更新控制
    要求: 禁止机器自动重启、禁止自动更新
    验证方式: 脚本执行
    
交付物:
  - 操作手册
  - 云上镜像包（可选）
  - 脚本执行报告
```
