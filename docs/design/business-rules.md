## 1. 计划管理规则

### 1.1 计划生命周期规则

```
草稿(DRAFT) → 待执行(PENDING) → 执行中(IN_PROGRESS) → 已完成(COMPLETED)
     ↓              ↓                    ↓                      ↑
   创建中      到达执行时间         核验任务进行中          所有任务完成
     ↓              ↓                    ↓                      ↑
   可编辑      自动/手动启动        进度实时更新           生成报告
```

**规则说明**:
1. **草稿状态(DRAFT)**: 
   - 可编辑所有字段
   - 不可启动核验任务
   - 可删除

2. **待执行状态(PENDING)**:
   - 到达计划执行时间前自动进入
   - 可手动提前启动
   - 不可修改计划基本信息

3. **执行中状态(IN_PROGRESS)**:
   - 工作流实例开始执行
   - 核验任务进行中
   - 可查看实时进度
   - 不可修改计划基本信息

4. **已完成状态(COMPLETED)**:
   - 所有核验任务完成
   - 生成最终报告
   - 归档保存

5. **已取消状态(CANCELLED)**:
   - 可随时取消（除已完成外）
   - 取消后释放关联资源标签

### 1.2 计划ID生成规则

**格式**: `PLAN-{YYYYMMDD}-{SEQUENCE}`

**示例**: `PLAN-20240322-001`

**规则**:
- 日期部分：计划创建日期
- 序列号：当日创建的第N个计划，3位数字，不足补零
- 全局唯一，不可重复

### 1.3 计划与工作流关联规则

#### 1.3.1 关联时机

1. **创建计划时关联**:
   - 选择既有标准工作流
   - 或创建新的自定义工作流
   - 系统自动创建工作流实例

2. **工作流实例绑定**:
   ```
   计划创建
       ↓
   选择工作流模板
       ↓
   系统创建工作流实例（草稿状态）
       ↓
   计划启动时 → 工作流实例启动
   ```

#### 1.3.2 工作流选择规则

| 计划分类 | 默认工作流 | 可选工作流 |
|---------|-----------|-----------|
| 标准上线(STANDARD) | 标准上线检查流程 | 所有已发布的工作流 |
| 业务需求(BUSINESS) | 业务变更检查流程 | 所有已发布的工作流 |

**规则**:
- 只能选择状态为 `active` 的工作流模板
- 选择后自动创建对应的工作流实例
- 计划与工作流实例一对一绑定

#### 1.3.3 数据标签生成规则

**标签格式**: `{PLAN-ID}-{CATEGORY-CODE}-{TIMESTAMP}`

**示例**: `PLAN-20240322-001-STD-1711072800`

**规则**:
- CATEGORY-CODE: `STD`(标准上线) 或 `BUS`(业务需求)
- TIMESTAMP: Unix时间戳，精确到秒
- 标签全局唯一，用于关联所有相关资源

### 1.4 计划优先级规则

| 优先级 | 编码 | 说明 | 默认处理策略 |
|-------|------|------|-------------|
| 紧急 | P0 | 影响生产环境的紧急变更 | 优先分配资源，立即处理 |
| 高 | P1 | 重要业务系统上线 | 优先处理，资源保障 |
| 中 | P2 | 常规业务变更 | 正常排队处理 |
| 低 | P3 | 非紧急变更、优化类 | 资源空闲时处理 |

**规则**:
- P0级别计划需要额外审批
- 同优先级按创建时间排序
- 可手动调整优先级（执行中除外）

### 1.5 计划时间规则

#### 1.5.1 时间字段定义

| 字段 | 说明 | 规则 |
|-----|------|------|
| planned_start_time | 计划执行时间 | 必须大于当前时间 |
| planned_end_time | 计划结束时间（预估） | 可选，必须大于计划执行时间 |
| actual_start_time | 实际开始时间 | 启动时自动记录 |
| actual_end_time | 实际结束时间 | 完成时自动记录 |

#### 1.5.2 延期检测规则

```python
def is_overdue(plan):
    if plan.status == 'COMPLETED':
        return False
    if plan.planned_start_time < now():
        return True
    return False
```

**规则**:
- 超过计划执行时间未启动，标记为延期
- 延期计划高亮显示，发送提醒
- 可手动调整计划时间（需说明原因）

### 1.6 审批材料规则

#### 1.6.1 材料类型

| 类型 | 编码 | 格式要求 | 必填 |
|-----|------|---------|------|
| 会议纪要 | meeting_minutes | PDF/Word/图片 | 是 |
| 审批邮件 | approval_email | PDF/图片 | 是 |
| 其他截图 | screenshot | 图片 | 否 |
| 其他材料 | other | 任意 | 否 |

**规则**:
- 至少上传一种审批材料
- 文件大小限制：单个文件最大20MB
- 支持批量上传
- 材料与计划生命周期绑定，不可单独删除计划

### 1.7 标签管理规则

#### 1.7.1 自动标签规则

**创建计划时自动打标签**:
```
计划创建
    ↓
涉及系统：订单系统、支付系统
    ↓
自动查询系统关联资源
    ↓
为以下资源自动打标签：
    - 订单系统的所有服务器
    - 支付系统的所有服务器
    - 相关账户信息
    - 相关数据库
```

#### 1.7.2 手动标签规则

1. **在台账管理中打标签**:
   - 选择服务器/账户/数据库
   - 选择要关联的计划
   - 系统自动打上计划标签

2. **在计划详情中管理标签**:
   - 查看已打标签的资源列表
   - 添加新的资源标签
   - 移除不需要的标签

#### 1.7.3 标签应用范围

| 核验任务 | 标签应用 |
|---------|---------|
| 服务对象台账 | 按标签筛选要收集台账的系统 |
| 基础资源交付 | 只检查带标签的服务器基线 |
| 权限移交 | 只检查带标签的账户权限 |
| 安全基线 | 只扫描带标签的服务器 |
| 监控告警 | 只配置带标签系统的监控 |

**规则**:
- 标签是核验范围的界定依据
- 无标签资源不纳入核验范围
- 标签在计划完成后可选择保留或清除

### 1.8 核验任务进度规则

#### 1.8.1 五大核验任务定义

| 序号 | 任务编码 | 任务名称 | 关联工作项类型 |
|-----|---------|---------|--------------|
| 1 | inventory | 服务对象台账 | inventory |
| 2 | resource_delivery | 基础资源交付 | resource_delivery |
| 3 | permission | 权限移交 | permission_handover |
| 4 | security | 安全基线 | security_baseline |
| 5 | monitoring | 监控告警 | monitoring |

#### 1.8.2 进度计算规则

```
整体进度 = Σ(各核验任务进度 × 权重) / 总权重

默认权重：
- 服务对象台账: 15%
- 基础资源交付: 25%
- 权限移交: 15%
- 安全基线: 25%
- 监控告警: 20%
```

**单个任务进度**:
```
任务进度 = (已完成检查项数 / 总检查项数) × 100%
```

#### 1.8.3 状态流转规则

```
PENDING → IN_PROGRESS → COMPLETED
              ↓
         FAILED (可重试)
```

**规则**:
- 所有任务初始状态为 PENDING
- 开始第一个检查项后变为 IN_PROGRESS
- 所有检查项完成后变为 COMPLETED
- 存在不通过项时，任务完成但标记有异常

## 2. 工作流管理规则

### 1.1 工作流模板生命周期

```
草稿(draft) → 发布(active) → 归档(archived)
   ↑____________↓
   (创建新版本)
```

**规则说明**:
1. **草稿状态**: 可随意编辑，不可创建实例
2. **发布状态**: 不可直接修改，需创建新版本
3. **归档状态**: 不可创建实例，仅保留历史记录
4. **版本管理**: 已发布的工作流修改时，自动创建新版本(v1.0 → v1.1)

### 1.2 预置工作流保护规则

| 规则项 | 说明 |
|-------|------|
| 不可删除 | 系统预置的三大核心检查项工作流不能删除 |
| 可自定义 | 可基于预置工作流创建副本进行自定义 |
| 版本继承 | 自定义工作流可继承预置标准的更新 |

### 1.3 工作项顺序规则

1. **默认顺序**: 按display_order字段升序排列
2. **依赖控制**: 有依赖的工作项必须在前置工作项完成后才能开始
3. **并行执行**: 无依赖关系的工作项可并行执行

## 2. 验收标准验证规则

### 2.1 验证方式优先级

```
脚本验证 > AI分析 > 人工核验
```

**规则说明**:
1. **脚本验证**: 最准确可靠，优先使用，直接在服务器执行
2. **AI分析**: 适用于文档类交付物，自动提取结论
3. **人工核验**: 作为补充手段，兜底确认

### 2.2 三大核心检查项详细验收标准

#### 2.2.1 服务对象台账收集 (inventory)

**1.1 应用系统台账表**

| 字段 | 必填 | 验证规则 |
|-----|------|---------|
| IP | 是 | IPv4格式，唯一性校验 |
| 主机名 | 是 | 长度1-64字符，符合主机名规范 |
| 配置 | 是 | CPU/内存/磁盘格式校验 |
| 用途 | 是 | 长度1-200字符 |
| 所属系统 | 是 | 关联系统名称 |
| 责任人 | 是 | 关联用户ID |
| 上线时间 | 是 | 日期格式，不能早于今天 |

**验证方式**: 人工核验
**交付物**: Excel表格

---

**1.2 云服务开通台账表**

**IAAS层必填项**:
- 计算服务: ECS/VM/容器实例列表

- 存储服务: 对象存储/块存储/NAS
- 备份服务: 快照/备份策略

**PAAS层必填项**:
- 数据库: MySQL/Redis/MongoDB等版本信息

**验证方式**: 人工核验

| 服务器名称 | 是 | 关联服务器 |

**交付物**: Excel表格

#### 2.2.2 基础资源标准化交付 (resource_delivery)

**2.1 生产环境上线前系统基线配置**

| 检查项ID | 检查内容 | 验证方式 | 通过标准 |
|---------|---------|---------|---------|
| 2.1.1 | 系统账户安全 | 脚本验证 | 符合《账户创建以及权限》基线 |

| 2.1.3 | 网络安全 | 脚本验证 | 防火墙规则符合最小化原则 |
| 2.1.4 | 系统基础环境配置 | 脚本验证 | NTP同步正常，字符集UTF-8 |

1. **执行环境**: SSH远程执行

**交付物**:
- 操作手册（配置步骤说明）

#### 2.2.3 安全基线核验 (security_baseline)

**安全加固报告核验**

| 检查项 | 验证方式 | 通过标准 |
|-------|---------|---------|
| 安全加固结论 | AI自动分析 | 报告明确标注"通过" |

**AI分析规则**:
1. **输入格式**: PDF/Word格式的安全扫描报告
2. **分析内容**: 提取报告结论部分
3. **关键词匹配**: "通过"/"合格"/"符合要求"等
4. **置信度阈值**: ≥0.85才算可靠
5. **人工复核**: AI结果需人工确认

**交付物**: 安全扫描报告（PDF/Word格式，安全团队提供）

---

### 2.3 结果判定规则

| 结果状态 | 判定条件 | 说明 |
|---------|---------|------|
| **通过** | 所有必填验收标准均满足 | 工作项完成，可进入下一步 |
| **不通过** | 存在必填验收标准不满足 | 需要整改后重新提交 |
| **待改进** | 非必填标准不满足，或存在建议项 | 可选优化，不影响上线 |
| **未开始** | 尚未进行分析或确认 | 初始状态 |

## 3. 脚本验证规则

### 3.1 脚本执行流程

```
选择验证脚本
    ↓
配置目标服务器连接信息(SSH)
    ↓
执行脚本（异步）
    ↓
捕获执行结果
    ↓
解析输出（JSON/文本）
    ↓
与验收标准比对
    ↓
生成验证报告
    ↓
保存为交付物
    ↓
自动判定结果
```

### 3.2 脚本输出格式规范

**JSON输出格式**:
```json
{
  "overall_result": "passed|failed|partial",
  "check_items": [
    {
      "id": "1",
      "name": "系统账户安全",
      "result": "passed|failed|na",
      "detail": "具体说明",
      "severity": "critical|high|medium|low"
    }
  ],
  "summary": {
    "total": 7,
    "passed": 6,
    "failed": 0,
    "na": 1
  },
  "execution_time_ms": 5230
}
```

### 3.3 脚本执行安全规则

1. **权限控制**: 仅授权服务器可执行脚本
2. **超时控制**: 默认300秒，防止脚本挂起
3. **输出限制**: 标准输出限制1MB
4. **敏感信息**: 脚本中不得包含密码等敏感信息
5. **审计日志**: 所有脚本执行记录审计日志

## 4. AI分析规则

### 4.1 AI分析流程

```
上传交付物
    ↓
文件格式检查
    ↓
内容提取（PDF/Word/Excel解析）
    ↓
AI分析（调用Kimi等服务）
    ↓
结果解析（通过/不通过/待改进）
    ↓
置信度评估
    ↓
生成分析报告
    ↓
人工复核确认
```

### 4.2 安全报告分析规则

**分析目标**: 判断安全加固是否通过

**分析步骤**:
1. **文档解析**: 提取PDF/Word文本内容
2. **结论定位**: 查找"结论"/"总结"/"Result"等章节
3. **关键词匹配**:
   - 通过类: "通过"、"合格"、"符合要求"、"Passed"
   - 不通过类: "不通过"、"不合格"、"存在风险"、"Failed"
4. **置信度计算**: 基于关键词匹配度和上下文

**输出结果**:
```json
{
  "result": "passed|failed",
  "confidence": 0.95,
  "evidence": "报告第3页结论部分明确标注：'本次安全加固检查通过'",
  "key_findings": ["未发现高危漏洞", "配置符合基线要求"]
}
```

### 4.3 AI服务配置规则

**支持的AI服务**:

| 服务 | 标识 | 适用场景 | 成本 |
|-----|------|---------|------|
| Kimi Code | kimi | 长文本报告分析 | 已有订阅 |
| 阿里云百炼 | bailian | 通用文档分析 | 按量付费 |

**配置规则**:
1. **默认服务**: Kimi Code（已有订阅）
2. **备用服务**: 阿里云百炼（预算申请后接入）
3. **超时时间**: 30秒
4. **重试次数**: 失败时重试2次

## 5. 工作流实例执行规则

### 5.1 实例状态流转

```
pending(待开始) 
    ↓ 用户启动
in_progress(进行中)
    ↓ 所有工作项完成
completed(已完成)
    ↓ 或
partial(部分完成)
    ↓ 或
cancelled(已取消)
```

### 5.2 工作项实例状态流转

```
pending(待开始)
    ↓ 前置条件满足
in_progress(进行中)
    ↓ 提交结果
pending_review(待审核) ──→ rejected(已驳回)
    ↓ 审核通过                    ↓ 重新提交
completed(已完成) ←──────────────┘
```

### 5.3 结果来源规则

| 来源 | 说明 | 优先级 |
|-----|------|-------|
| auto | 自动分析生成（脚本/AI） | 高 |
| manual | 人工输入/确认 | 低（可覆盖auto） |

**规则**:
1. 自动分析结果可被人工覆盖
2. 人工覆盖需填写原因
3. 覆盖操作记录审计日志

## 10. 知识库管理规则

### 10.1 知识分类规则

#### 10.1.1 预置分类保护

| 规则项 | 说明 |
|-------|------|
| 不可删除 | 五大核心功能预置分类不能删除（INV/RSD/PHO/SBL/MON） |
| 可扩展 | 可在预置分类下创建子分类 |
| 编码唯一 | 分类编码全局唯一，区分大小写 |

#### 10.1.2 分类与工作项类型关联

| 分类编码 | 关联工作项类型 | 匹配优先级 |
|---------|--------------|-----------|
| INV | inventory | 100% |
| RSD | resource_delivery | 100% |
| PHO | permission_handover | 100% |
| SBL | security_baseline | 100% |
| MON | monitoring | 100% |
| 自定义 | 用户指定 | 80% |

### 10.2 知识条目规则

#### 10.2.1 内容类型与验证方式映射

| 内容类型 | 默认验证方式 | 说明 |
|---------|-------------|------|
| requirement | manual | 验收要求，人工核验 |
| baseline | script | 基线标准，脚本验证 |
| manual | manual | 操作手册，人工核验 |
| checklist | manual/script | 检查清单，视内容而定 |
| script | script | 验证脚本，自动执行 |

#### 10.2.2 文档格式转换规则

**Markdown导入**:
- 标题(# ## ###) → 检查项标题
- 列表项(- *) → 检查项内容
- 表格 → 结构化数据

**Word导入**:
- 章节标题 → 检查项标题
- 段落 → 检查项内容
- 表格 → 结构化数据

**Excel导入**:
- 每行 → 一个检查项
- 列映射 → 检查项字段
- 必填列: 检查项名称、检查内容

### 10.3 智能匹配规则

#### 10.3.1 匹配算法权重

| 匹配维度 | 权重 | 计算方式 |
|---------|------|---------|
| 工作项类型匹配 | 40% | 完全匹配=1.0，部分匹配=0.5 |
| 关键词匹配 | 30% | TF-IDF算法计算相似度 |
| 分类匹配 | 20% | 同分类=1.0，子分类=0.8 |
| 使用频率 | 10% | 归一化使用次数 |

#### 10.3.2 匹配阈值

| 匹配分数 | 等级 | 处理建议 |
|---------|------|---------|
| ≥0.90 | 高匹配 | 自动推荐，优先展示 |
| 0.70-0.89 | 中匹配 | 推荐展示，用户选择 |
| 0.50-0.69 | 低匹配 | 可选展示 |
| <0.50 | 不匹配 | 不展示 |

#### 10.3.3 自动生成规则

**从知识条目生成验收标准**:

1. **标题映射**: 知识条目标题 → 验收标准内容
2. **验证方式确定**: 根据内容类型确定验证方式
3. **交付物推断**: 
   - script类型 → 脚本执行报告
   - manual类型 → 相关文档/表格
   - ai类型 → 分析报告
4. **必填项默认**: 默认为必填，用户可调整

**生成置信度计算**:
```
confidence = (匹配分数 × 0.4) + (内容完整度 × 0.3) + (历史准确率 × 0.3)
```

### 10.4 验收标准与知识库关联规则

#### 10.4.1 关联方式

| 关联方式 | 说明 | 使用场景 |
|---------|------|---------|
| 自动生成 | 从知识条目自动生成 | 新建验收标准时 |
| 手动关联 | 用户手动选择知识条目 | 编辑验收标准时 |
| 智能推荐 | 系统推荐，用户确认 | 配置工作项时 |

#### 10.4.2 版本锁定规则

1. **创建时锁定**: 验收标准创建时，锁定引用的知识条目版本
2. **更新提示**: 知识条目更新后，提示用户验收标准可更新
3. **批量更新**: 支持批量更新引用同一知识条目的所有验收标准

#### 10.4.3 关联影响范围

当知识条目更新时:

| 更新类型 | 影响范围 | 处理方式 |
|---------|---------|---------|
| 错别字修正 | 无影响 | 静默更新 |
| 内容补充 | 可选更新 | 提示用户，可选更新 |
| 要求变更 | 必须确认 | 强制提示，需人工确认 |
| 删除条目 | 影响关联 | 禁止删除，需先解除关联 |

### 10.5 版本管理规则

#### 10.5.1 版本号规则

采用语义化版本控制:
```
主版本号.次版本号.修订号
v1.2.3
```

| 版本变更 | 触发条件 | 示例 |
|---------|---------|------|
| 主版本号+1 | 重大变更，不兼容 | v1.x → v2.0 |
| 次版本号+1 | 功能新增，兼容 | v1.1 → v1.2 |
| 修订号+1 | 缺陷修复，兼容 | v1.1.0 → v1.1.1 |

#### 10.5.2 版本创建规则

1. **草稿状态**: 编辑不创建新版本
2. **发布状态**: 
   - 内容变更 → 必须创建新版本
   - 元数据变更 → 可选创建版本
3. **版本对比**: 支持任意两个版本的差异对比

### 10.6 知识库使用统计

#### 10.6.1 统计维度

| 维度 | 说明 |
|-----|------|
| 使用次数 | 被引用生成验收标准的次数 |
| 匹配次数 | 被智能匹配推荐的次数 |
| 采纳率 | 推荐后被采纳的比例 |
| 更新频率 | 内容更新的频率 |

#### 10.6.2 热度计算

```
热度分 = (使用次数 × 0.4) + (匹配次数 × 0.3) + (采纳率 × 100 × 0.3)
```
