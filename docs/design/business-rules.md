## 2. 计划管理规则

### 2.1 计划生命周期规则

```
草稿(DRAFT) → 待执行(PENDING) → 执行中(IN_PROGRESS) → 已完成(COMPLETED)
     │              │                    │                      ↑
     │              │                    │                      │
   创建中      到达执行时间         核验进行中              全部完成
   可编辑      或手动启动           进度实时更新            生成报告
```

**规则说明**:

1. **草稿状态(DRAFT)**:
   - 可编辑所有字段
   - 不可启动核验任务
   - 可删除
   - 创建后默认状态

2. **待执行状态(PENDING)**:
   - 到达计划执行时间前自动进入
   - 可手动提前启动
   - 不可修改计划基本信息
   - 可取消计划

3. **执行中状态(IN_PROGRESS)**:
   - 工作流实例开始执行
   - 核验任务进行中
   - 可查看实时进度
   - 不可修改计划基本信息
   - 不可取消计划

4. **已完成状态(COMPLETED)**:
   - 所有核验任务完成
   - 生成最终报告
   - 归档保存
   - 不可修改任何信息

5. **已取消状态(CANCELLED)**:
   - 可随时取消（除已完成外）
   - 取消后释放关联资源标签
   - 保留历史记录

### 2.2 计划ID生成规则

**格式**: `PLAN-{YYYYMMDD}-{SEQUENCE}`

**示例**: `PLAN-20240322-001`

**规则**:
- 日期部分：计划创建日期
- 序列号：当日创建的第N个计划，3位数字，不足补零
- 全局唯一，不可重复
- 生成后不可修改

### 2.3 计划与工作流关联规则

#### 2.3.1 关联时机

1. **创建计划时关联**:
   - 选择既有标准工作流
   - 或创建新的自定义工作流
   - 系统自动创建工作流实例

2. **工作流实例绑定**:
   ```
   计划创建
       ↓
   选择工作流模板
       ↓
   系统创建工作流实例（草稿状态）
       ↓
   计划启动时 → 工作流实例启动
   ```

#### 2.3.2 工作流选择规则

| 计划分类 | 默认工作流 | 可选工作流 |
|---------|-----------|-----------|
| 标准上线(STANDARD) | 标准上线检查流程 | 所有已发布的工作流 |
| 业务需求(BUSINESS) | 业务变更检查流程 | 所有已发布的工作流 |

**规则**:
- 只能选择状态为 `active` 的工作流模板
- 选择后自动创建对应的工作流实例
- 计划与工作流实例一对一绑定
- 工作流实例状态跟随计划状态变化

#### 2.3.3 数据标签生成规则

**标签格式**: `{PLAN-ID}-{CATEGORY-CODE}-{TIMESTAMP}`

**示例**: `PLAN-20240322-001-STD-1711072800`

**规则**:
- CATEGORY-CODE: `STD`(标准上线) 或 `BUS`(业务需求)
- TIMESTAMP: Unix时间戳，精确到秒
- 标签全局唯一，用于关联所有相关资源
- 创建计划时自动生成

### 2.4 计划优先级规则

| 优先级 | 编码 | 说明 | 默认处理策略 |
|-------|------|------|-------------|
| 紧急 | P0 | 影响生产环境的紧急变更 | 优先分配资源，立即处理 |
| 高 | P1 | 重要业务系统上线 | 优先处理，资源保障 |
| 中 | P2 | 常规业务变更 | 正常排队处理 |
| 低 | P3 | 非紧急变更、优化类 | 资源空闲时处理 |

**规则**:
- P0级别计划需要额外审批
- 同优先级按创建时间排序
- 可手动调整优先级（执行中除外）
- 优先级影响资源分配和处理顺序

### 2.5 计划时间规则

#### 2.5.1 时间字段定义

| 字段 | 说明 | 规则 |
|-----|------|------|
| planned_start_time | 计划执行时间 | 必须大于当前时间 |
| planned_end_time | 计划结束时间（预估） | 可选，必须大于计划执行时间 |
| actual_start_time | 实际开始时间 | 启动时自动记录 |
| actual_end_time | 实际结束时间 | 完成时自动记录 |

#### 2.5.2 延期检测规则

```python
def is_overdue(plan):
    if plan.status == 'COMPLETED':
        return False
    if plan.planned_start_time < now():
        return True
    return False
```

**规则**:
- 超过计划执行时间未启动，标记为延期
- 延期计划高亮显示，发送提醒
- 可手动调整计划时间（需说明原因）
- 延期记录保留用于统计分析

### 2.6 审批材料规则

#### 2.6.1 材料类型

| 类型 | 编码 | 格式要求 | 必填 |
|-----|------|---------|------|
| 会议纪要 | meeting_minutes | PDF/Word/图片 | 是 |
| 审批邮件 | approval_email | PDF/图片 | 是 |
| 其他截图 | screenshot | 图片 | 否 |
| 其他材料 | other | 任意 | 否 |

**规则**:
- 至少上传一种审批材料
- 文件大小限制：单个文件最大20MB
- 支持批量上传
- 材料与计划生命周期绑定，不可单独删除计划
- 支持版本管理，可上传多个版本

### 2.7 标签管理规则

#### 2.7.1 自动标签规则

**创建计划时自动打标签**:
```
计划创建
    ↓
涉及系统：订单系统、支付系统
    ↓
自动查询系统关联资源
    ↓
为以下资源自动打标签：
    - 订单系统的所有服务器
    - 支付系统的所有服务器
    - 相关账户信息
    - 相关数据库
```

#### 2.7.2 手动标签规则

1. **在台账管理中打标签**:
   - 选择服务器/账户/数据库
   - 选择要关联的计划
   - 系统自动打上计划标签

2. **在计划详情中管理标签**:
   - 查看已打标签的资源列表
   - 添加新的资源标签
   - 移除不需要的标签

#### 2.7.3 标签应用范围

| 核验任务 | 标签应用 |
|---------|---------|
| 服务对象台账 | 按标签筛选要收集台账的系统 |
| 基础资源交付 | 只检查带标签的服务器基线 |
| 权限移交 | 只检查带标签的账户权限 |
| 安全基线 | 只扫描带标签的服务器 |
| 监控告警 | 只配置带标签系统的监控 |

**规则**:
- 标签是核验范围的界定依据
- 无标签资源不纳入核验范围
- 标签在计划完成后可选择保留或清除
- 支持标签继承（子系统继承父系统标签）

### 2.8 核验任务进度规则

#### 2.8.1 五大核验任务定义

| 序号 | 任务编码 | 任务名称 | 关联工作项类型 |
|-----|---------|---------|--------------|
| 1 | inventory | 服务对象台账 | inventory |
| 2 | resource_delivery | 基础资源交付 | resource_delivery |
| 3 | permission | 权限移交 | permission_handover |
| 4 | security | 安全基线 | security_baseline |
| 5 | monitoring | 监控告警 | monitoring |

#### 2.8.2 进度计算规则

```
整体进度 = Σ(各核验任务进度 × 权重) / 总权重

默认权重：
- 服务对象台账: 15%
- 基础资源交付: 25%
- 权限移交: 15%
- 安全基线: 25%
- 监控告警: 20%
```

**单个任务进度**:
```
任务进度 = (已完成检查项数 / 总检查项数) × 100%
```

#### 2.8.3 状态流转规则

```
PENDING → IN_PROGRESS → COMPLETED
              ↓
         FAILED (可重试)
```

**规则**:
- 所有任务初始状态为 PENDING
- 开始第一个检查项后变为 IN_PROGRESS
- 所有检查项完成后变为 COMPLETED
- 存在不通过项时，任务完成但标记有异常

## 3. 工作流管理规则

### 3.1 工作流模板生命周期

```
草稿(draft) → 发布(active) → 归档(archived)
   ↑____________↓
   (创建新版本)
```

**规则说明**:
1. **草稿状态**: 可随意编辑，不可创建实例
2. **发布状态**: 不可直接修改，需创建新版本
3. **归档状态**: 不可创建实例，仅保留历史记录
4. **版本管理**: 已发布的工作流修改时，自动创建新版本(v1.0 → v1.1)

### 3.2 预置工作流保护规则

| 规则项 | 说明 |
|-------|------|
| 不可删除 | 系统预置的三大核心检查项工作流不能删除 |
| 可自定义 | 可基于预置工作流创建副本进行自定义 |
| 版本继承 | 自定义工作流可继承预置标准的更新 |

### 3.3 工作项顺序规则

1. **默认顺序**: 按display_order字段升序排列
2. **依赖控制**: 有依赖的工作项必须在前置工作项完成后才能开始
3. **并行执行**: 无依赖关系的工作项可并行执行

### 3.4 工作项层级规则

#### 3.4.1 层级定义

| 层级 | 说明 | 示例 |
|-----|------|------|
| 父工作项(parent) | 5大核心分类，parent_id为NULL | 服务对象台账收集 |
| 子工作项(child) | 具体检查项，parent_id指向父工作项 | 应用系统台账表 |

#### 3.4.2 父子关联规则

**创建规则**:
1. 子工作项创建时必须指定父工作项（parent_id必填）
2. 父工作项必须是work_item_level='parent'的记录
3. 子工作项自动继承父工作项的work_item_type
4. 一个父工作项可以有多个子工作项
5. 子工作项的parent_id创建后不可更改

**删除规则**:
1. 父工作项下有子工作项时，需先删除所有子工作项
2. 系统预置的子工作项不可删除，只能禁用（status='disabled'）
3. 已关联验收标准的子工作项不可删除

**修改规则**:
1. 不可修改parent_id（父子关系创建时确定）
2. 不可修改work_item_level
3. 系统预置工作项的名称、类型不可修改
4. 可修改字段：名称（非预置）、描述、交付物要求、验证方式

#### 3.4.3 5大父工作项定义（系统预置）

| 编码 | 名称 | work_item_type | 子工作项数量 |
|-----|------|----------------|-------------|
| wi-001 | 服务对象台账收集 | inventory | 3个 |
| wi-002 | 基础资源标准化交付 | resource_delivery | 2个 |
| wi-003 | 安全基线核验 | security_baseline | 1个 |
| wi-004 | 生产环境权限移交 | permission_handover | 1个 |
| wi-005 | 监控告警配置确认 | monitoring | 1个 |

#### 3.4.4 子工作项创建流程

```
选择父工作项（5大类之一）
    ↓
填写子工作项信息
    ├── 名称（如：应用系统台账表）
    ├── 描述
    ├── 验证方式（人工/脚本/AI）
    ├── 交付物要求
    └── 验收标准
    ↓
系统自动关联
    ├── parent_id = 父工作项ID
    ├── work_item_type = 父工作项类型
    └── work_item_level = 'child'
    ↓
保存子工作项
```

#### 3.4.5 验收标准配置时的层级显示

**配置验收标准时，必须显示完整的层级信息**:

```
工作项：应用系统台账表
父工作项：服务对象台账收集
```

**数据关联**:
- 验收标准绑定到子工作项（acceptance_criteria.work_item_id = child_work_item.id）
- 通过子工作项的parent_id关联到父工作项
- 查询时返回完整的层级结构：
  ```json
  {
    "work_item": {
      "id": "wi-001-01",
      "name": "应用系统台账表",
      "parent": {
        "id": "wi-001",
        "name": "服务对象台账收集"
      }
    }
  }
  ```

## 4. 核验执行规则

### 4.1 验证方式优先级

```
脚本验证 > AI分析 > 人工核验
```

**规则说明**:
1. **脚本验证**: 最准确可靠，优先使用，直接在服务器执行
2. **AI分析**: 适用于文档类交付物，自动提取结论
3. **人工核验**: 作为补充手段，兜底确认

### 4.2 三大核心检查项详细验收标准

#### 4.2.1 服务对象台账收集 (inventory)

**1.1 应用系统台账表**

| 字段 | 必填 | 验证规则 |
|-----|------|---------|
| IP | 是 | IPv4格式，唯一性校验 |
| 主机名 | 是 | 长度1-64字符，符合主机名规范 |
| 配置 | 是 | CPU/内存/磁盘格式校验 |
| 用途 | 是 | 长度1-200字符 |
| 所属系统 | 是 | 关联系统名称 |
| 责任人 | 是 | 关联用户ID |
| 上线时间 | 是 | 日期格式，不能早于今天 |

**验证方式**: 人工核验
**交付物**: Excel表格

---

**1.2 云服务开通台账表**

**IAAS层必填项**:
- 计算服务: ECS/VM/容器实例列表
- 网络服务: VPC/SLB/安全组配置
- 存储服务: 对象存储/块存储/NAS
- 备份服务: 快照/备份策略

**PAAS层必填项**:
- 数据库: MySQL/Redis/MongoDB等版本信息
- 消息队列: Kafka/RabbitMQ等版本信息
- 缓存服务: 类型和版本
- 其他中间件: 类型和版本

**验证方式**: 人工核验
**交付物**: Excel表格

---

**1.3 系统及软件账户台账表**

| 字段 | 必填 | 验证规则 |
|-----|------|---------|
| 系统名称 | 是 | 关联应用系统 |
| 服务器名称 | 是 | 关联服务器 |
| IP | 是 | IPv4格式 |
| 系统账户名 | 是 | 长度1-32字符 |
| 软件账户名 | 否 | 长度1-32字符 |
| 权限级别 | 是 | 枚举: admin/operator/viewer |
| 持有人 | 是 | 关联用户ID |
| 有效期 | 是 | 日期格式，必须大于今天 |
| 密码修改周期 | 是 | 数字，单位: 天 |

**验证方式**: 人工核验
**交付物**: Excel表格

#### 4.2.2 基础资源标准化交付 (resource_delivery)

**2.1 生产环境上线前系统基线配置**

| 检查项ID | 检查内容 | 验证方式 | 通过标准 |
|---------|---------|---------|---------|
| 2.1.1 | 系统账户安全 | 脚本验证 | 符合《账户创建以及权限》基线 |
| 2.1.2 | 磁盘分区合规 | 脚本验证 | 系统盘与数据盘已分离 |
| 2.1.3 | 网络安全 | 脚本验证 | 防火墙规则符合最小化原则 |
| 2.1.4 | 系统基础环境配置 | 脚本验证 | NTP同步正常，字符集UTF-8 |
| 2.1.5 | 自动更新控制 | 脚本验证 | 自动更新已禁用 |
| 2.1.6 | 证书管理 | 脚本验证 | 证书已导入(如有需要) |
| 2.1.7 | 其他安全基线 | 脚本验证 | 符合组织安全基线要求 |

**脚本执行规则**:
1. **执行环境**: SSH远程执行
2. **执行用户**: 具有sudo权限的运维账户
3. **超时时间**: 300秒
4. **输出格式**: JSON
5. **结果判定**: 所有检查项通过才算整体通过

**交付物**:
- 操作手册（配置步骤说明）
- 云上镜像包（可选）
- 脚本执行报告（自动生成）

**2.2 生产环境软件标准化部署**

| 检查项ID | 检查内容 | 验证方式 | 通过标准 |
|---------|---------|---------|---------|
| 2.2.1 | 安装路径规范 | 脚本验证 | 符合《软件创建及目录权限》基线 |
| 2.2.2 | 安装脚本规范 | 脚本验证 | 符合bash4.0标准 |
| 2.2.3 | 一键部署支持 | 脚本验证 | 可一键成功部署 |
| 2.2.4 | 日志记录保存 | 脚本验证 | 安装日志完整保存 |

**脚本执行规则**:
1. **语法检查**: 安装脚本必须符合bash4.0标准
2. **路径检查**: 验证安装路径和权限
3. **部署测试**: 支持一键部署验证
4. **日志检查**: 验证安装日志存在且完整

**交付物**:
- 操作手册（部署步骤说明）
- 安装脚本（符合bash4.0标准）
- 安装日志（记录部署过程）

#### 4.2.3 安全基线核验 (security_baseline)

**安全加固报告核验**

| 检查项 | 验证方式 | 通过标准 |
|-------|---------|---------|
| 安全加固结论 | AI自动分析 | 报告明确标注"通过" |
| 高危漏洞数量 | AI自动分析 | 高危漏洞数量为0 |
| 中危漏洞数量 | AI自动分析 | 中危漏洞数量≤5 |
| 低危漏洞数量 | AI自动分析 | 记录但不影响通过 |

**AI分析规则**:
1. **文档格式**: 支持PDF、Word、Excel格式
2. **关键字段提取**: 结论、漏洞等级、数量
3. **置信度要求**: ≥0.85
4. **人工复核**: 高风险项目需人工确认

**交付物**:
- 安全扫描报告（PDF/Word格式）
- 漏洞修复证明（如有）

### 4.3 交付物状态流转规则

```
待上传(PENDING) → 已上传(UPLOADED) → 核验中(VERIFYING) → 已通过(PASSED)
                        ↓
                    不通过(FAILED) / 待改进(IMPROVEMENT)
                        ↓
                    重新上传(REUPLOAD)
```

**状态说明**:
- **待上传**: 工作项创建后的初始状态
- **已上传**: 交付物上传完成
- **核验中**: 核验任务已触发，正在执行
- **已通过**: 核验结论为"通过"
- **不通过**: 核验结论为"不通过"
- **待改进**: 核验结论为"待改进"
- **重新上传**: 需要重新准备交付物

**流转规则**:
1. 同一工作项可上传多个版本的交付物
2. 新版本交付物上传后，旧版本自动归档
3. 核验结论只针对最新版本的交付物
4. "不通过"状态必须重新上传才能再次核验
5. "待改进"状态可选择通过，但需记录改进要求

### 4.4 核验结论判定规则

#### 4.4.1 结论类型

| 结论 | 编码 | 说明 | 颜色标识 | 后续操作 |
|-----|------|------|---------|---------|
| 通过 | passed | 完全符合验收标准 | 绿色(#52c41a) | 标记完成，进入下一工作项 |
| 不通过 | failed | 不符合验收标准 | 红色(#ff4d4f) | 退回，要求重新准备 |
| 待改进 | improvement | 基本符合，有优化空间 | 橙色(#faad14) | 记录问题，允许通过但需后续改进 |

#### 4.4.2 判定标准

**人工核验判定**:
- 通过：所有必填检查项都符合要求
- 不通过：存在不符合要求的检查项
- 待改进：基本符合要求，但存在可优化项

**脚本验证判定**:
- 通过：脚本执行成功，所有检查项返回"passed"
- 不通过：脚本执行失败，或存在检查项返回"failed"
- 待改进：脚本执行成功，但存在警告信息

**AI分析判定**:
- 通过：AI提取的结论为"通过"，置信度≥0.85
- 不通过：AI提取的结论为"不通过"，置信度≥0.85
- 待改进：AI提取的结论为"待改进"，或置信度<0.85

#### 4.4.3 结果记录规则

1. **核验结果必须包含**:
   - 核验方式（人工/脚本/AI）
   - 核验结论（通过/不通过/待改进）
   - 核验时间
   - 核验人（人工核验时）
   - 核验证据（截图、报告等）
   - 备注说明

2. **结果追溯**:
   - 所有核验结果永久保存
   - 支持历史版本对比
   - 支持核验过程回放（脚本验证）
   - 支持AI分析过程查看

## 5. 知识库管理规则

### 5.1 知识分类规则

**分类体系**:
```
知识库分类
├── 基线规范
│   ├── 系统基线
│   ├── 网络基线
│   ├── 安全基线
│   └── 应用基线
├── 操作手册
│   ├── 系统安装
│   ├── 软件部署
│   ├── 配置管理
│   └── 故障处理
├── 最佳实践
│   ├── 架构设计
│   ├── 性能优化
│   ├── 安全加固
│   └── 监控告警
└── 模板库
    ├── 验收标准模板
    ├── 检查清单模板
    ├── 报告模板
    └── 脚本模板
```

**分类规则**:
- 分类支持多级嵌套（最多3级）
- 每个分类关联特定的工作项类型
- 预置分类不可删除，只能禁用
- 自定义分类可自由增删改

### 5.2 版本管理规则

**版本号格式**: `v{major}.{minor}.{patch}`

**示例**: `v1.0.0`, `v1.1.0`, `v2.0.0`

**版本规则**:
- major: 重大内容变更，不兼容更新
- minor: 功能新增，向下兼容
- patch: 错误修复，完全兼容
- 初始版本默认为 `v1.0.0`
- 发布后的知识条目修改时自动创建新版本
- 支持版本回退和版本对比

### 5.3 智能匹配规则

**匹配算法**:
1. **关键词匹配**: 基于TF-IDF的文本相似度
2. **语义匹配**: 基于预训练模型的语义相似度
3. **规则匹配**: 基于预定义规则的精确匹配

**匹配流程**:
```
用户输入验收标准需求
    ↓
关键词提取和预处理
    ↓
多维度匹配算法执行
    ├── 关键词匹配（权重40%）
    ├── 语义匹配（权重40%）
    └── 规则匹配（权重20%）
    ↓
综合评分排序
    ↓
返回Top N推荐结果
```

**匹配阈值**:
- 高匹配：相似度≥0.9，直接推荐
- 中匹配：相似度0.7-0.9，展示供选择
- 低匹配：相似度<0.7，不推荐
