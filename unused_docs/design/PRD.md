## 1. 产品概述

### 1.1 产品定位

**赛领OpsPilot管理平台**是一个面向运维专家和运维管理者的**计划驱动型准入管理系统**。系统帮助运维管理者在接到上线计划、变更计划等工作需求时，通过标准化的流程管理，确保所有交付物符合准入要求。

### 1.2 核心业务流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      赛领OpsPilot管理平台 - 核心业务流程                     │
└─────────────────────────────────────────────────────────────────────────────┘

    接收工作需求                    制定管理计划                    执行核验
         │                              │                             │
         ▼                              ▼                             ▼
┌─────────────────┐           ┌─────────────────┐           ┌─────────────────┐
│ 运维管理者收到   │           │ 1. 创建计划      │           │ 7. 上传交付物   │
│ 上线/变更计划   │──────────▶│ 2. 选择范围     │──────────▶│ 8. 触发核验     │
│ (线下已审批)    │           │ 3. 拆解工作项   │           │ 9. 得出核验结论 │
└─────────────────┘           │ 4. 制定验收标准 │           └─────────────────┘
                              │ 5. 排列工作流   │
                              │ 6. 线下沟通要求 │
                              └─────────────────┘
                                       │
                                       ▼
                              ┌─────────────────┐
                              │ 各团队准备交付物 │
                              │ (线下执行)      │
                              └─────────────────┘
```

### 1.3 目标用户

| 用户角色 | 主要职责 | 使用场景 |
|---------|---------|---------|
| **甲方运维经理** | 计划制定、范围选择、工作流编排、核验审批、外包交付质量管理 | 创建计划、选择台账范围、拆解工作项、审核交付物、查看外包团队交付质量统计 |
| **甲方运维专家** | 定义标准模板、配置验证规则、制定验收标准 | 维护SOP预置模板、配置脚本和AI分析规则、审核关键交付物 |
| **乙方外部服务团队** | 按工作项要求执行具体任务、准备并上传交付物 | 接收工作项任务、执行任务步骤、上传交付物、更新任务进度 |

### 1.4 核心价值

1. **计划驱动**：以计划为核心，所有工作围绕计划展开
2. **台账联动**：计划与台账管理深度关联，自动识别新增/更新需求
3. **标准化拆解**：将复杂计划拆解为可执行的工作项清单
4. **多维度核验**：人工、脚本、AI三种核验方式
5. **全链路追踪**：从计划创建到核验完成的完整追溯

## 3. 详细业务流程

### 3.1 第一阶段：计划制定

#### 3.1.1 接收工作需求

**触发条件**：运维管理者收到来自平台负责人的上线计划申请（线下已审批通过）

**输入**：
- 上线/变更申请（线下审批通过）
- 涉及的应用系统清单
- 计划执行时间要求

#### 3.1.2 创建计划

**操作步骤**：
1. 进入计划管理模块
2. 点击"创建计划"
3. 填写计划基本信息：
   - 计划名称
   - 计划分类（见下方分类体系）
   - 优先级（P0-P3）
   - 执行时间
   - 计划说明
4. 上传审批材料：
   - 会议纪要
   - 审批邮件
   - 其他截图

**计划分类与范围选择对应关系**（更新后）：

| 计划分类 | 说明 | 范围选择调用接口 | 操作类型 | 自动生成工作项 |
|---------|------|-----------------|----------|---------------|
| **新系统上线** | 全新业务系统首次上线 | 台账管理-新增应用系统台账 | 创建新台账 | 补充应用系统台账 |
| **新功能发布** | 现有系统新增功能模块上线 | 台账管理-查询应用系统台账 | 查询+编辑台账 | 补充新增的功能模块 |
| **业务功能变更** | 业务逻辑调整、功能优化 | 台账管理-查询应用系统台账 | 查询+勾选台账 | 更新应用系统台账 |
| **数据库变更** | 数据库结构变更、数据迁移 | 台账管理-查询应用系统台账 | 查询+勾选台账 | 更新数据库相关台账 |

### 3.1.5 SOP模板引擎设计（新增）

#### 3.1.5.1 模板引擎概述

SOP（Standard Operating Procedure）模板引擎是系统的核心支撑模块，由**甲方运维专家**预先配置，在**甲方运维经理**创建计划时自动应用，为**乙方外部服务团队**提供标准化的工作指引。

**核心价值**：
- **标准化**：固化运维最佳实践，确保交付质量一致性
- **自动化**：根据计划分类自动匹配模板，减少人工配置
- **强制管控**：通过流程节点控制，确保关键步骤不遗漏

#### 3.1.5.2 模板分类体系

| 模板分类 | 适用场景 | 预置工作项组合 | 典型交付物 |
|---------|---------|---------------|-----------|
| **新系统上线模板** | 全新业务系统首次上线 | 台账补充+基础资源+安全基线+权限移交+监控告警 | 部署方案、基线检查报告、安全扫描报告 |
| **新功能发布模板** | 现有系统新增功能模块 | 功能模块补充+基础资源+监控告警 | 功能设计文档、部署方案、监控配置 |
| **业务功能变更模板** | 业务逻辑调整、功能优化 | 台账更新+影响评估+回归测试 | 变更方案、测试报告、回滚方案 |
| **数据库变更模板** | 数据库结构变更、数据迁移 | 台账更新+数据备份+变更实施+验证 | 变更方案、备份记录、验证报告 |

#### 3.1.5.3 工作项模板配置

**配置主体**：甲方运维专家

**配置内容**：

#### 3.1.5.4 审核等级与审核矩阵

**审核等级定义**：

| 审核等级 | 定义 | 典型工作项 | 审核方式 |
|---------|------|-----------|---------|
| **普通项** | 标准化程度高、风险可控的工作项 | 基础资源申请、常规监控配置 | 乙方自审/脚本自动核验/甲方抽检 |
| **关键项** | 影响核心业务、存在安全风险的工作项 | 部署方案文档、安全基线检查、权限移交 | 强制甲方专家人工审核 |

**审核矩阵配置**：

```yaml
# 审核矩阵（由甲方运维专家配置）
audit_matrix:
  # 普通项审核规则
  normal_item:
    primary_audit: "乙方自审"  # 主要审核方式
    secondary_audit: "脚本自动核验"  # 辅助审核方式
    sampling_ratio: 0.3  # 甲方抽检比例（30%）
    auto_pass_threshold: 0.95  # 脚本置信度≥95%可自动通过
    
  # 关键项审核规则
  critical_item:
    primary_audit: "甲方专家人工审核"  # 必须人工审核
    mandatory_reviewer: "运维专家"  # 指定审核人角色
    secondary_audit: "AI辅助分析"  # AI提供分析建议
    auto_pass_threshold: null  # 关键项不支持自动通过
    escalation_rule: "审核不通过时，自动通知乙方负责人重新提交"
```

**强制管控规则**：

| 规则类型 | 规则说明 | 系统行为 |
|---------|---------|---------|
| **交付物必传** | 节点准出条件要求上传交付物 | 未上传交付物，"提交审核"按钮禁用 |
| **审核必过** | 关键项必须通过甲方审核 | 审核不通过，自动退回乙方，无法流转 |
| **顺序执行** | 工作项按预设顺序执行 | 前置工作项未完成，后续工作项锁定 |
| **权限控制** | 不同角色可操作的范围不同 | 乙方无法修改甲方配置的验收标准 |

### 3.2 第二阶段：验收标准制定

#### 3.2.1 为子工作项制定验收标准

**操作步骤**：
1. 选择需要制定验收标准的子工作项
2. 选择验收标准来源：
   - **预置模板**：从知识库选择标准模板
   - **文档导入**：导入MD/Word/Excel格式的基线要求
   - **手动输入**：自定义输入验收标准
3. 配置核验方式：
   - 人工核验
   - 脚本自动核验
   - AI智能分析
4. 定义交付物要求（格式、内容要求）

**验收标准组成**（以"补充应用系统台账"为例）：

| 要素 | 说明 | 示例 |
|-----|------|------|
| 检查项 | 具体的检查内容 | "应用系统名称已填写" |
| 核验方式 | 如何验证 | 人工核验 |
| 通过标准 | 怎样算通过 | 字段不为空且格式正确 |
| 交付物 | 需要提交的材料 | 应用系统台账表（Excel） |

### 3.3 第三阶段：交付物准备与收集

#### 3.3.1 各团队准备交付物

**执行方**：各业务团队（线下执行）

**工作内容**：
- 按照工作项要求准备交付物
- 确保交付物符合验收标准
- 在计划执行时间前完成准备

#### 3.3.2 上传交付物

**操作步骤**：
1. 进入计划详情页
2. 找到对应的工作项
3. 点击"上传交付物"
4. 选择文件并上传（支持PDF、Word、Excel、图片等格式）
5. 填写交付物说明

**交付物状态流转**：

```
待上传 → 已上传 → 核验中 → 已通过
                    ↓
                 不通过/待改进
                    ↓
                 重新上传
```

### 3.4 第四阶段：核验执行

#### 3.4.1 触发核验

**触发条件**：交付物上传完成后，系统自动或手动触发核验

#### 3.4.2 执行核验

根据配置的核验方式，执行相应的核验操作：

**方式一：人工核验**
- 运维管理者查看交付物
- 对照验收标准进行检查
- 人工判断是否通过

**方式二：脚本自动核验**
- 系统自动执行预设脚本
- 脚本在目标服务器上运行
- 自动比对结果，生成报告

**方式三：AI智能分析**
- 系统自动解析交付物内容（如PDF报告）
- AI提取关键信息（如"通过"/"不通过"结论）
- 自动生成分析结果

#### 3.4.3 记录核验结论

**核验结论类型**：

| 结论 | 说明 | 后续操作 |
|-----|------|---------|
| **通过** | 交付物符合验收标准 | 标记完成，进入下一工作项 |
| **不通过** | 交付物不符合要求 | 退回，要求重新准备 |
| **待改进** | 基本符合，但有优化空间 | 记录问题，允许通过但需后续改进 |

### 3.5 第五阶段：计划完成

#### 3.5.1 计划状态更新

当所有工作项的核验结论都已确定后：
- 系统自动计算计划整体进度
- 更新计划状态为"已完成"
- 生成计划执行报告

#### 3.5.2 归档与复盘

- 所有交付物归档保存
- 核验结果汇总生成报告
- 支持后续审计和复盘分析

### 6.1 术语表

| 术语 | 说明 |
|-----|------|
| Plan | 计划，运维工作的基本单元 |
| Work Item | 工作项，计划拆解后的具体任务 |
| Workflow Template | 工作流模板，预定义的工作项组合和管控规则 |
| Template Instance | 模板实例，基于工作流模板动态生成的具体工作流 |
| Inventory | 台账，系统基础数据记录 |
| Deliverable | 交付物，工作项产出的文档或数据 |
| Criteria | 验收标准，核验交付物的依据 |

### 6.2 计划分类与台账管理接口对照表

| 计划分类 | 台账管理接口 | 操作类型 | 范围选择说明 | 自动生成工作项 |
|---------|-------------|---------|-------------|---------------|
| 新系统上线 | 新增应用系统台账 | 创建新台账 | 填写应用系统基础信息，含功能模块和模块上线时间 | 补充应用系统台账 |
| 新功能发布 | 查询应用系统台账 | 查询+编辑 | 选择已有台账，编辑功能模块和模块上线时间 | 补充新增的功能模块 |
| 业务功能变更 | 查询应用系统台账 | 查询+勾选 | 从台账列表中勾选涉及的应用系统（可多选） | 更新应用系统台账 |
| 数据库变更 | 查询应用系统台账 | 查询+勾选 | 从台账列表中勾选涉及的应用系统（可多选） | 更新数据库相关台账 |

**说明**：
- **新系统上线**：调用"新增应用系统台账"接口创建新台账，需填写完整的应用系统信息
- **新功能发布**：调用"查询应用系统台账"接口，选择后允许编辑功能模块和模块上线时间
- **业务功能变更**：调用"查询应用系统台账"接口，仅允许勾选已有台账（可多选）
- **数据库变更**：调用"查询应用系统台账"接口，仅允许勾选已有台账（可多选），不勾选云服务台账
